# Store 8 — Admin App (Flutter)

Client-facing app: manage the catalogue (Category → Product → Brand → Size, same flow as the
storefront) and get an instant notification whenever a customer places an order — including
while the app is closed or the phone was offline.

## First-time setup

1. Follow `../../SETUP.md` to create the Firebase project and get your keys.
2. From this folder:
   ```bash
   flutter pub get
   dart pub global activate flutterfire_cli
   flutterfire configure --project=<your-firebase-project-id>
   ```
   This overwrites `lib/firebase_options.dart` with your real project config and drops
   `google-services.json` (Android) / `GoogleService-Info.plist` (iOS) into place automatically.
3. Generate the real app icon + splash screen from the brand logo already in `assets/branding/`:
   ```bash
   dart run flutter_launcher_icons
   dart run flutter_native_splash:create
   ```
4. Run it:
   ```bash
   flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000   # Android emulator -> your local backend
   ```
   Use your machine's LAN IP instead of `10.0.2.2` for a physical device on the same network, or
   your deployed backend URL once it's hosted.
5. iOS only, one manual step Apple requires (no code change can do this for you): in Xcode, open
   `ios/Runner.xcworkspace` → target Runner → Signing & Capabilities → **+ Capability** → add
   *Push Notifications* and *Background Modes* (tick *Remote notifications* — already declared in
   Info.plist, this just confirms the capability). Then upload your APNs key to the Firebase
   console (Project settings → Cloud Messaging → Apple app configuration).

## Notes
- `android/app/build.gradle.kts` still uses the Flutter default package `com.example.store8` — see
  the `TODO` comment there for how to rename it (Android Studio → Refactor → Rename package)
  before you publish. There's a harmless unused `MainActivity.kt` at
  `android/app/src/main/kotlin/com/store8/admin/` left over from drafting this — safe to delete.
- No secrets are hardcoded: the backend URL comes from `--dart-define=API_BASE_URL=...` (see
  `lib/core/config.dart`), and the Firebase config comes from `lib/firebase_options.dart`
  (generated by `flutterfire configure`, not something you type in by hand).
- All screens are responsive (built with `Expanded`/`Wrap`/`ListView`, no fixed pixel layouts) and
  tested against phone and tablet aspect ratios.

## Structure
```
lib/
  core/            theme, router (go_router), api client (Dio + auto auth header), shared widgets
  features/
    auth/           Firebase Auth sign-in + backend admin allow-list check, splash, login
    notifications/  FCM: foreground/background/terminated handling, token registration
    catalog/        categories/brands/products/items — models, service, provider, screens
    orders/         order list/detail, status updates
    dashboard/      bottom-nav shell (Orders / Catalogue / Account)
```
